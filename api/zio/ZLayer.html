ZLayer

zio.ZLayer
See theZLayer companion object
sealed abstract class ZLayer[-RIn, +E, +ROut]

A ZLayer[RIn, E, ROut] describes how to build one or more services of type ROut in your application, given the services RIn they depend on. Building the layer may fail with an error of type E. Services can be injected into effects via ZIO#provide. Effects can require services via ZIO.service.

Layer can be thought of as recipes for producing bundles of services, given their dependencies (other services).

Construction of services can be effectful and utilize resources that must be acquired and safely released when the services are done being utilized. ZLayer.scoped acquires a resource in the scope of the layer, and the resource is released when that scope closes, for example when the effect that a layer was provided to completes.

Within one build (one provide or one build call), a layer value that appears several times is built once and its services are shared, except that the layers inside a fresh layer are built apart from the rest of the build. Each separate provide or build call builds it again. fresh opts a layer out of sharing, and memoize shares a layer across several provideLayer calls.

++ combines two layers horizontally: it builds them in parallel and has the inputs and outputs of both. >>> combines them vertically: it feeds the outputs of the first layer into the second one. >+> does the same but also keeps the outputs of the first layer. With >>>, the resources of the second layer are released before those of the first one.

final case class DbConfig(url: String)

final class Database(config: DbConfig) {
 def query(sql: String): UIO[String] = ZIO.succeed(config.url + " ran " + sql)
}

final class UserRepo(db: Database) {
 def countUsers: UIO[String] = db.query("SELECT count(*) FROM users")
}

val configLayer: ULayer[DbConfig] =
 ZLayer.succeed(DbConfig("jdbc:postgresql://localhost:5432/shop"))

val databaseLayer: ZLayer[DbConfig, Nothing, Database] =
 ZLayer.scoped {
   for {
     config
             ZIO.debug("closing database")
           )
   } yield db
 }

val userRepoLayer: ZLayer[Database, Nothing, UserRepo] =
 ZLayer.fromFunction((db: Database) => new UserRepo(db))

val appLayer: ULayer[UserRepo] = configLayer >>> databaseLayer >>> userRepoLayer

val program: UIO[String] = ZIO.serviceWithZIO[UserRepo](_.countUsers).provide(appLayer)
// prints "opening database", then "closing database" once countUsers is done
// result: jdbc:postgresql://localhost:5432/shop ran SELECT count(*) FROM users

Because of their composition properties, layers are the idiomatic way in ZIO to create services that depend on other services.

final def fresh: ZLayer[RIn, E, ROut]

Creates a fresh version of this layer that will not be shared.

Creates a fresh version of this layer that will not be shared.

Each occurrence of the fresh layer in a build builds it again, instead of reusing the services of the same layer built elsewhere in that build. The layers inside the fresh layer are built again as well, even when the same layers are also built elsewhere in that build; within the fresh layer they are still shared.

val buildCounts: UIO[(Int, Int)] =
 for {
   builds &lt;- Ref.make(0)
   cache   = ZLayer(builds.updateAndGet(_ + 1))
   _      &lt;- ZIO.scoped((cache ++ cache).build)
   shared &lt;- builds.getAndSet(0)
   _      &lt;- ZIO.scoped((cache ++ cache.fresh).build)
   fresh  &lt;- builds.get
 } yield (shared, fresh)
// (1,2)
