Schedule

zio.Schedule
See theSchedule companion object
trait Schedule[-Env, -In, +Out] extends Serializable

A Schedule[Env, In, Out] describes when and how many times an effect recurs. At each step it receives an input of type In, produces an output of type Out, and decides either to stop or to continue after a delay. It may use an environment of type Env.

Use a schedule with ZIO#repeat, where the input is the effect's success value, or with ZIO#retry, where the input is the effect's error. Recurrences come after the first run, so with Schedule.recurs(3) an effect runs at most four times.

Each step that continues returns a set of time intervals (Schedule.Intervals), and the effect runs again at the start of the earliest one. Schedules combine in three main ways:

  • Intersection (&&): continues while both schedules continue, and waits for the longer of the two delays.
  • Union (||): continues while either schedule continues, and waits for the shorter of the two delays.
  • Sequence (andThen): runs this schedule until it is done, then the other one.

Inputs and outputs can also be transformed (map, contramap), used to stop a schedule early (whileInput, untilOutput), and the delays changed (jittered, modifyDelay). The companion object holds the common schedules, such as recurs, spaced, exponential and the calendar schedules.

def connect(attempts: Ref[Int]): IO[String, String] =
 attempts.updateAndGet(_ + 1).flatMap { n =>
   if (n &lt; 3) ZIO.fail("attempt " + n + " failed")
   else ZIO.succeed("connected on attempt " + n)
 }

// waits 100 ms, then 200 ms, 400 ms, ...; gives up after 5 retries
val policy: Schedule[Any, Any, (Duration, Long)] =
 Schedule.exponential(100.millis) && Schedule.recurs(5)

val program: IO[String, String] =
 Ref.make(0).flatMap(attempts => connect(attempts).retry(policy))
// succeeds with "connected on attempt 3"

Each step outputs the value accumulated before that step's output is folded in, and the step that ends the schedule outputs the value folded from all earlier outputs. For example, Schedule.recurs(3) outputs 0, 1, 2 and then 3 when it stops, so Schedule.recurs(3).fold(100L)(_ + _) outputs 100, 100, 101 and then 103.

final def ||[Env1 <: Env, In1 <: In, Out2](that: Schedule[Env1, In1, Out2])(implicit zippable: Zippable[Out, Out2]): WithState[(State, State), Env1, In1, zippable.Out]

Returns a new schedule that continues while either schedule continues, and outputs both outputs together. Each step uses the union of the two schedules' intervals, so it waits for the shorter of the two delays: Schedule.spaced(1.second) || Schedule.spaced(3.seconds) waits 1 second each time. Once one schedule is done, the other one's intervals are used.
