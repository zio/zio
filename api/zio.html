sealed abstract class Cause[+E] extends Product, Serializable

A Cause[E] describes why an effect failed, and can hold several reasons at once. Its leaves are the typed failures of type E (Fail), the defects, which are unexpected Throwables (Die), and the interruptions, which record the id of the interrupting fiber (Interrupt). Then composes two causes that happened in sequence, such as a failure followed by a failing finalizer, and Both composes two causes that happened in parallel, such as the failures of two zipPar branches. Empty is the cause with nothing in it, and Stackless wraps a cause to control how much of the JVM stack trace prettyPrint shows.

A Cause[E] describes why an effect failed, and can hold several reasons at once. Its leaves are the typed failures of type E (Fail), the defects, which are unexpected Throwables (Die), and the interruptions, which record the id of the interrupting fiber (Interrupt). Then composes two causes that happened in sequence, such as a failure followed by a failing finalizer, and Both composes two causes that happened in parallel, such as the failures of two zipPar branches. Empty is the cause with nothing in it, and Stackless wraps a cause to control how much of the JVM stack trace prettyPrint shows.

val timeout: Cause[String] = Cause.fail("timeout")
val crash: Cause[Nothing]  = Cause.die(new IllegalStateException("crash"))

val parallel: Cause[String]   = timeout && crash
val sequential: Cause[String] = timeout ++ Cause.fail("retry failed")

val failures: List[String] = sequential.failures
// List(timeout, retry failed)
val defects: List[String] = parallel.defects.map(_.getMessage)
// List(crash)
val commutes: Boolean = (timeout && crash) == (crash && timeout)
// true

sealed abstract class Chunk[+A] extends ChunkLike[A], Serializable

A Chunk[A] is an immutable, indexed sequence of values of type A. Chunks are usually backed by arrays, but expose an immutable interface to the underlying elements, and they become lazy on operations that would be costly with arrays, such as repeated concatenation.

A Chunk[A] is an immutable, indexed sequence of values of type A. Chunks are usually backed by arrays, but expose an immutable interface to the underlying elements, and they become lazy on operations that would be costly with arrays, such as repeated concatenation.

Chunks built from primitive values, for example with Chunk.fromArray(Array(1, 2, 3)), keep them in a primitive array without boxing. A chunk can also mix primitive types, as in Chunk[AnyVal](1, 2.0). On the JVM, a null that follows a primitive first element becomes that primitive's zero value: Chunk[Any](1, null) is Chunk(1, 0). Besides the Scala collection operations, a chunk has effectful variants such as mapZIO, filterZIO and foldZIO.

val numbers: Chunk[Int] = Chunk(1, 2, 3) ++ Chunk.fromIterable(List(4, 5))
val evens: Chunk[Int]   = numbers.filter(_ % 2 == 0).map(_ * 10)
val second: Int         = numbers(1)
val asList: List[Int]   = evens.toList
// evens  == Chunk(20, 40)
// second == 2
// asList == List(20, 40)

The implementation of balanced concatenation is based on the one for Conc-Trees in "Conc-Trees for Functional and Parallel Programming" by Aleksandar Prokopec and Martin Odersky. http://aleksandar-prokopec.com/resources/docs/lcpc-conc-trees.pdf

A zio.Config describes the structure of some configuration data.

A Config[A] holds no data: it describes how to read a value of type A, and a ConfigProvider loads it. ZIO.config loads it with the provider of the current fiber, which by default reads each value from the environment variables and then from the system properties. Primitive descriptions such as Config.int("port") or Config.string("host") read one value under a name. nested puts a description under a parent name, ++ (or zip) combines two descriptions into a tuple, || (or orElse) reads another description when this one fails, and optional and withDefault handle missing data. map, mapOrFail and validate convert or check the value, Config.listOf and Config.table read sequences and maps, and Config.secret reads a value whose toString hides it.

trait Differ[Value, Patch] extends Serializable

A Differ[Value, Patch] knows how to compare an old value and new value of type Value to produce a patch of type Patch that describes the differences between those values. A Differ also knows how to apply a patch to an old value to produce a new value that represents the old value updated with the changes described by the patch.

A Differ[Value, Patch] knows how to compare an old value and new value of type Value to produce a patch of type Patch that describes the differences between those values. A Differ also knows how to apply a patch to an old value to produce a new value that represents the old value updated with the changes described by the patch.

A Differ can be used to construct a FiberRef supporting compositional updates using the FiberRef.makePatch constructor. When forked fibers join, their changes are merged as patches rather than replaced: with Differ.set, two fibers that each add a different element both leave their element in the joined value, while with Differ.update the last fiber to join wins.

The Differ companion object contains constructors for Differ values for common data types such as Chunk, Map, and Set. In addition, Differ values can be transformed using the transform operator and combined using the orElseEither and zip operators. This allows creating Differ values for arbitrarily complex data types compositionally.

val differ = Differ.set[Int]

val patch   = differ.diff(Set(1, 2, 3), Set(2, 3, 4))
val updated = differ.patch(patch)(Set(1, 2, 3))
// Set(2, 3, 4)

val add2   = differ.diff(Set(1), Set(1, 2))
val add3   = differ.diff(Set(1), Set(1, 3))
val merged = differ.patch(differ.combine(add2, add3))(Set(1))
// Set(1, 2, 3)

A Fiber[E, A] is a handle to a computation that runs concurrently with the code that started it, and that ends with a failure of type E or a value of type A. A Fiber[E, A] is a handle to a computation that runs concurrently with the code that started it, and that ends with a failure of type E or a value of type A. A fiber is a lightweight thread of execution that never consumes more than a whole thread (but may consume much less, depending on contention and asynchronicity).

Forking an effect (ZIO#fork and its variants) starts it on a new Fiber.Runtime. Combinators such as zip, orElse and map, and constructors such as Fiber.succeed or Fiber.fromFuture, build a Fiber.Synthetic fiber out of other fibers or values.

 for {
   sumFiber   &lt;- ZIO.succeed((1 to 10).sum).fork
   sum        &lt;- sumFiber.join
   failing    &lt;- ZIO.fail("invalid order").fork
   failedExit &lt;- failing.await
   sleeping   &lt;- ZIO.never.fork
   stopped    &lt;- sleeping.interrupt
 } yield (sum, failedExit.isFailure, stopped.isInterrupted)

sealed trait FiberRef[A] extends Serializable

A FiberRef is ZIO's equivalent of Java's ThreadLocal. The value of a FiberRef is automatically propagated to child fibers when they are forked and merged back in to the value of the parent fiber after they are joined.

A FiberRef is ZIO's equivalent of Java's ThreadLocal. The value of a FiberRef is automatically propagated to child fibers when they are forked and merged back in to the value of the parent fiber after they are joined.

Each fiber has its own value: a fiber reads the initial value until it, or a parent before forking it, sets one. A forked child starts with its parent's value, and the changes a fiber makes are not seen by other fibers that run at the same time. When the parent holds a value for the FiberRef (it set or inherited one, or created the FiberRef with FiberRef.make), the fork function of FiberRef.make transforms it for the child; otherwise the child reads the initial value unchanged. Fiber#join merges the child's value back into the joining fiber; Fiber#await does not.

val program: UIO[(String, String, String)] =
 ZIO.scoped {
   for {
     user       &lt;- FiberRef.make("anonymous")
     _          &lt;- user.set("alice")
     child      &lt;- user.getAndSet("bob").fork
     _          &lt;- child.await
     afterAwait &lt;- user.get
     inherited  &lt;- child.join
     afterJoin  &lt;- user.get
   } yield (inherited, afterAwait, afterJoin)
 }
// succeeds with (alice,alice,bob)

Here the child sees "alice" when it starts, the parent still sees "alice" after await, and the parent sees "bob" once it has joined the child.

By default the value of the child fiber will replace the value of the parent fiber on join but you can specify your own logic for how values should be merged.

val merged: UIO[Int] =
 ZIO.scoped {
   for {
     fiberRef &lt;- FiberRef.make(0, identity[Int], math.max)
     child    &lt;- fiberRef.update(_ + 1).fork
     _        &lt;- fiberRef.update(_ + 2)
     _        &lt;- child.join
     value    &lt;- fiberRef.get
   } yield value
 }
// succeeds with 2

Here value will be 2 as the value in the joined fiber is lower and we specified max as our combining function.

sealed abstract class Hub[A]

A Hub is an asynchronous message hub. Publishers can offer messages to the hub and subscribers can subscribe to take messages from the hub.

A Hub is an asynchronous message hub. Publishers can offer messages to the hub and subscribers can subscribe to take messages from the hub.

Subscribers do not compete for messages: each subscriber takes them on its own, whereas each value offered to a Queue goes to one taker. With Hub.bounded and Hub.unbounded, a subscriber receives each message published while it is subscribed. With Hub.dropping and Hub.sliding, it can miss the messages that the hub dropped while it was full. subscribe returns a Dequeue that stays subscribed until its Scope closes. A message published while there are no subscribers is not kept.

A bounded hub keeps each message until every subscriber has taken it, or, with Hub.sliding, until a newer message replaces it. When it is full, what publish does depends on how the hub was made:

  • Hub.bounded suspends the publishing fiber until there is room (back pressure).
  • Hub.dropping drops the new message, and publish returns false.
  • Hub.sliding drops the oldest message to make room for the new one.
  • Hub.unbounded has a capacity of Int.MaxValue.
val program: UIO[(Chunk[String], Chunk[String])] =
 ZIO.scoped {
   for {
     hub    &lt;- Hub.bounded[String](8)
     first  &lt;- hub.subscribe
     second &lt;- hub.subscribe
     _      &lt;- hub.publishAll(List("a", "b"))
     a      &lt;- first.takeAll
     b      &lt;- second.takeN(2)

A Schedule[Env, In, Out] describes when and how many times an effect recurs. At each step it receives an input of type In, produces an output of type Out, and decides either to stop or to continue after a delay. It may use an environment of type Env.

A Schedule[Env, In, Out] describes when and how many times an effect recurs. At each step it receives an input of type In, produces an output of type Out, and decides either to stop or to continue after a delay. It may use an environment of type Env.

Use a schedule with ZIO#repeat, where the input is the effect's success value, or with ZIO#retry, where the input is the effect's error. Recurrences come after the first run, so with Schedule.recurs(3) an effect runs at most four times.

Each step that continues returns a set of time intervals (Schedule.Intervals), and the effect runs again at the start of the earliest one. Schedules combine in three main ways:

  • Intersection (&&): continues while both schedules continue, and waits for the longer of the two delays.
  • Union (||): continues while either schedule continues, and waits for the shorter of the two delays.
  • Sequence (andThen): runs this schedule until it is done, then the other one.

Inputs and outputs can also be transformed (map, contramap), used to stop a schedule early (whileInput, untilOutput), and the delays changed (jittered, modifyDelay). The companion object holds the common schedules, such as recurs, spaced, exponential and the calendar schedules.

sealed trait ZIO[-R, +E, +A] extends Product, Serializable

A ZIO[R, E, A] value is an immutable value (called an "effect") that describes an async, concurrent workflow. In order to be executed, the workflow requires a value of type ZEnvironment[R], and when executed, the workflow will either produce a failure of type E, or a success of type A.

A ZIO[R, E, A] value is an immutable value (called an "effect") that describes an async, concurrent workflow. In order to be executed, the workflow requires a value of type ZEnvironment[R], and when executed, the workflow will either produce a failure of type E, or a success of type A.

The three type parameters:

  • R is the environment the workflow needs. Any means it needs nothing.
  • E is the type of the error it may fail with. Nothing means it cannot fail.
  • A is the type of the value it succeeds with.

ZIO effects may informally be thought of as functions of the form ZEnvironment[R] => Either[E, A].

An effect is lazy: creating it runs nothing. It runs when a Runtime executes it (for example as the run effect of a ZIOAppDefault), and it runs again each time it is executed.

ZIO effects model resourceful interaction with the outside world, including synchronous, asynchronous, concurrent, and parallel interaction.

The async and concurrent operations of ZIO effects are powered by fibers, which are lightweight, green threads that enable high scalability.

To run an effect, you need a Runtime, which is capable of executing effects. A runtime holds the environment, the fiber-local values (FiberRefs) and the runtime flags that the effects it runs start with.

sealed abstract class ZLayer[-RIn, +E, +ROut]

A ZLayer[RIn, E, ROut] describes how to build one or more services of type ROut in your application, given the services RIn they depend on. Building the layer may fail with an error of type E. Services can be injected into effects via ZIO#provide. Effects can require services via ZIO.service.

A ZLayer[RIn, E, ROut] describes how to build one or more services of type ROut in your application, given the services RIn they depend on. Building the layer may fail with an error of type E. Services can be injected into effects via ZIO#provide. Effects can require services via ZIO.service.

Layer can be thought of as recipes for producing bundles of services, given their dependencies (other services).

Construction of services can be effectful and utilize resources that must be acquired and safely released when the services are done being utilized. ZLayer.scoped acquires a resource in the scope of the layer, and the resource is released when that scope closes, for example when the effect that a layer was provided to completes.

Within one build (one provide or one build call), a layer value that appears several times is built once and its services are shared, except that the layers inside a fresh layer are built apart from the rest of the build. Each separate provide or build call builds it again. fresh opts a layer out of sharing, and memoize shares a layer across several provideLayer calls.

++ combines two layers horizontally: it builds them in parallel and has the inputs and outputs of both. >>> combines them vertically: it feeds the outputs of the first layer into the second one. >+> does the same but also keeps the outputs of the first layer. With >>>, the resources of the second layer are released before those of the first one.
